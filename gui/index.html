8. Judges

      
Um Judge é o "perfil de uso" do avaliador — igual um Agent (aba 5), mas do lado de quem julga em vez de quem resolve: qual --agent do Harbor roda o julgamento, com qual model (só os high-tier da lista curada), quais instruções e quais Judge Rubrics (aba 7) marcar por padrão. Cadastre um aqui e reaproveite na aba Compare, na aba Analyze e no pin de rubric de uma Task — em vez de escolher model/rubric soltos toda vez.

      
Sobre "skills": diferente do Agent, não dá pra anexar uma skill (SKILL.md) de verdade ao Judge — conferido no código do Harbor instalado (harbor/analyze/analyzer.py): o harbor analyze monta o agente avaliador sem nunca setar .skills, e o comando analyze não tem flag --skill (diferente do harbor run, que tem). O que dá pra fazer de verdade é reescrever as instruções do juiz por completo (abaixo) — é a única alavanca que o Harbor expõe pra moldar como ele avalia.

1. Provider API keys

      
Comece por aqui. Cadastre a chave de cada provider que for usar — os models e agents das próximas abas mostram se a chave esperada já está configurada. Gravadas localmente em secrets.env (state dir do kit), não como variável de ambiente do Windows/sistema — só entram no ambiente do processo `harbor`/`podman` que a GUI dispara, na hora da run, e em mais nenhum lugar. 9. Create a task (harbor init --task)

      
Uma task é o problema que o agent vai tentar resolver na aba Compare (código-base, instruções, testes). Gera o esqueleto de arquivos aqui; depois você edita instruction.md, o Dockerfile, e o teste de verificação manualmente. Os evals/*/seed-task deste kit são só exemplos vazios — crie a sua própria aqui.

      

        

          

          

        

        
Vira o nome da pasta da task (dentro do Output dir) e o identificador que aparece na lista abaixo e no seletor de task da aba Compare. "Org" é só um prefixo/namespace (ex.: minha-org/minha-task) — pode deixar em branco se o Name já tiver a barra.


        

          

          

        

        
"Output dir" é onde a pasta da task vai ser criada em disco (ex.: .\evals\python\my-task) — é esse caminho que você depois cola no campo "Task / dataset path" da aba Compare. "Steps" define se a task é de um passo só (0 — o normal: 1 instruction.md, 1 test.sh) ou de N passos sequenciais (gera steps/step-1/, steps/step-2/, ... cada um com sua própria instruction.md e test.sh; se um passo falhar, os seguintes não rodam). Use N>0 só se a task representa um fluxo de várias etapas dependentes — na dúvida, deixe 0.


        
        
        
        
        
Description e Author são só metadados gravados no task.toml da task (aparecem pra quem for ler/reusar a task depois) — não afetam a execução.


        

        

        
Por padrão o esqueleto já vem com um tests/test.sh de exemplo baseado em pytest e um solution/solve.sh de referência — marque pra pular um deles se for escrever o seu do zero num formato diferente (ex.: teste não-Python, ou task sem solução de referência).

Datasets

      
O que é: um dataset é um pacote de tasks já prontas, publicado por terceiros (benchmarks conhecidos, coleções de exercícios de outros times) — o oposto de criar sua própria task do zero na aba Tasks. Quando usar: quando você quer comparar agents/models contra um benchmark já validado e conhecido (em vez de uma task sua), ou só quer ver exemplos de tasks bem escritas antes de criar as suas. Quando pular: se você só vai usar tasks próprias (aba 9), esta aba inteira é opcional — não é um pré-requisito de nada.

      
Como usar: 1) baixe um dataset pelo nome (form abaixo); 2) as tasks dele aparecem sozinhas em datasets/<nome>/<task>/ — o mesmo escaneamento que lista suas tasks próprias (aba Tasks) também lista essas, e elas entram automaticamente no seletor de task da aba Compare. Não existe um "modo dataset" separado: depois de baixado, uma task de dataset se comporta exatamente como uma task sua.

      
      
Este botão só imprime um link pro Hub do Harbor (catálogo de datasets publicados) — nesta versão do Harbor o CLI ainda não lista os nomes disponíveis diretamente no terminal, então é preciso abrir esse link no navegador pra descobrir o nome exato do dataset que você quer baixar. Limitação do `harbor dataset list` em si, não desta UI.

      

        

          

          

        

        
O nome vem do link do Hub acima (não tem preenchimento automático — copie o nome exato de lá). "Output dir" é a pasta onde as tasks baixadas vão ficar; o padrão "datasets" é o que a aba Tasks/Compare já sabe escanear — só troque se tiver um motivo específico pra organizar em outro lugar.

        
      

      

      

    

  


  
  

    

      
Trajectory viewer (harbor view)

      
O que é: um segundo servidor web (do próprio Harbor, não desta GUI) que abre numa aba nova e mostra, passo a passo, tudo que o agent fez dentro do container numa run: comandos executados, arquivos lidos/editados, saída de cada ferramenta, a resposta do modelo em cada turno. É a evidência bruta por trás do número de reward. Quando usar: depois de rodar uma comparação (aba 10), quando o reward sozinho não explica o suficiente — reward baixo e você quer ver onde o agent travou, reward alto e você quer confirmar que não foi um atalho/gambiarra, ou só quer entender o estilo de trabalho de um agent específico. É complementar ao Analyze (aba Analyze/painel do Compare): Analyze dá um veredito resumido de um LLM juiz; aqui você vê a trajetória inteira com os próprios olhos, sem intermediário.

      
Como usar: aponte pro mesmo "Jobs dir" que você usou na run do Compare (o botão "Ver trajetórias" que aparece ali já faz isso sozinho, sem precisar vir nesta aba) e clique "Start viewer" — abre um link pra uma aba nova. É um processo de vida longa (fica rodando escutando numa porta) até você clicar "Stop" na lista abaixo ou fechar o `gui-server`.

Rubric analysis (harbor analyze)

      
Pede pra um Judge (aba 8 — sempre high-tier, nunca o default barato do Harbor) ler a trajetória de um job já rodado (aba 10) e dar um veredito PASS/FAIL por critério de um rubric (aba 7) — complementa o reward numérico do Compare, é bom pra detectar reward hacking ou desempatar candidatos que já passaram. Precisa de uma chave de provider cadastrada em Secrets (aba 1) para o agente avaliador. Normalmente você vai preferir o botão "Analisar" direto na tabela de resultados do Compare — esta aba é pra uso ad-hoc num path específico.
